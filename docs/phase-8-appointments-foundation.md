# Phase 8 appointments foundation

Cal.com is the first live appointments candidate because it already exists in the shared provider catalog and supports availability plus booking lifecycle through one API. The adapter uses API v2 version `2026-02-25`, bearer credentials, request timeouts, approval references, and idempotency keys.

`LIVE_APPOINTMENTS_ENABLED=false` keeps every live request blocked by default. `VERTICAL_RELEASE_GATING_ENABLED` and `VERTICAL_RELEASE_RULES` provide the second release boundary by domain, provider, and release level. Sandbox appointment flows remain available.

Repository coverage now includes availability search, approved idempotent creation, status reads, approved cancellation, and approved rescheduling that requires a slot checked within the previous five minutes. Successful mutations synchronize the canonical `Appointment` and `LifeTransaction` records without creating a parallel booking model.

The lifecycle path is durable and remains behind `LIVE_APPOINTMENTS_ENABLED`. Cal.com callbacks are authenticated against the exact raw request body with HMAC-SHA256, constrained to a replay window, deduplicated by a content hash, and persisted as durable jobs. Callback payloads cannot create appointments by trusting metadata alone: an existing user-owned booking correlation is required. Every accepted lifecycle event also schedules an authoritative provider reconciliation job with bounded retries and dead-letter visibility. Operational summaries count pending and dead-lettered callback and reconciliation jobs.

Automated acceptance covers invalid signatures, stale replay attempts, duplicate delivery, uncorrelated callback isolation, canonical state updates, stale-slot reschedule rejection, reschedule deduplication, and retryable provider network failure. Formal live launch still requires a real Cal.com developer/OAuth credential, webhook secret provisioning, regional/privacy review, support ownership, staging evidence against a real Cal.com test account, and explicit activation. Current endpoint and webhook shapes were checked against the official Cal.com API v2 documentation on 2026-08-29.

The Appointment Coordinator now receives appointment-specific chat starters before generic email suggestions. Provider discovery prompts extract specialty and location, availability prompts extract a provider identifier and date range, and booking-management prompts extract the requested operation without fabricating an approval reference. This makes safe discovery and availability usable through the normal agent chat while preserving the existing approval boundary for every mutation.
